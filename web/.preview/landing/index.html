$ whatis ply

Containers, shipped
like packages.

ply is a daemonless container runtime and package manager. One static binary. Images named by what they are, pinned by sha256. Dependencies declared like npm, resolved like Go, run like processes.

$ curl -fsSL https://plybox.sh/install.sh | sh

~/api 
$ ply build .

built  api-0.1.0-linux-x64.img (18.2 MiB)
$ ply run api --scale 3
✓ api ×3 · healthy · 10.77.0.2-4
$ ply deploy api
✓ rolled 3/3, health-gated, zero downtime

$ ply --features

no daemon

Containers are plain child processes. Nothing resident, nothing to babysit, no socket owning your machine.

content-addressed

Filenames claim identity, hashes prove it. ply.lock pins every dependency to a sha256 — same lock, same bytes.

any host is a registry

GitHub Releases, an R2 bucket, a plain directory. Fetch is construct URL → GET → verify hash. Zero API.

deterministic deps

Semver ranges resolved by minimal version selection. No dependency hell, no surprise upgrades.

rootless & hardened

Security tiers, seccomp, cgroups, per-app network namespaces. Runs rootful or rootless.

built for prod

Health gates, restart policies, ply deploy rolls, systemd & load-balancer emitters.

$ cat ply.toml

[package]
name = "api"
version = "0.1.0"
entrypoint = ["python3", "server.py"]

[dependencies]
base = "alpine@3.20"
python3 = "3.12"
jq = "1.7"

[sources]
default = "https://registry.plybox.sh/ply/{package}"

The manifest is human intent; the lockfile is machine truth. ply build resolves ranges to exact versions, pins hashes, and produces a single .img you can run anywhere — or publish by copying the file to any host you control.

The official registry mirrors mainstream Alpine packages as ready-to-use images, served from a global CDN. Append-only: a version, once published, never changes.
